# 跨项目公众号素材积累的 3 句标准话术

> **一句话**：用 3 句标准话术，让任何项目的素材积累自动跑起来，不用每次重复强调规则。
> **场景**：建每个新项目（含跨项目搬判断） / 工作中沉淀 / 对话收尾
> **来源**：2026-10-16 东哥问「除了第一句话，还有第二句话吗？」+「第 1 句、第 4 句，是不是一样的内容？」合并

---

## 问题的本质

**老痛点**：东哥每次建新项目都要跟 Claude 重新说一遍「记素材 / 沉淀 / 2 层粒度 / 4 个判断 / 6 类 / 5 模板」。

**东哥原话**：「你把这些规则写成一个 skill，以便于我建每个项目时，都能直接用，就不用再重复强调一大堆规则。」

**隐藏问题**：skill 写得再详细，**没有触发话术 = 用不起来**。
- 新项目第一次对话说什么？
- 工作中说什么？
- 结束前说什么？
- 跨项目复制说什么？

**迭代过程**：
- **v1（4 句版）**：建库 / 过程 / 结束 / 跨项目复制
- **v2（澄清歧义）**：跨项目复制默认全搬 → 东哥问「会把其他项目的内容也复制到新项目中，不只是规则和方法？」→ 改为 3 选项
- **v3（3 句合并）**：东哥问「第 1 句、第 4 句，是不是一样的内容？」→ 跨项目搬判断嵌入第 1 句，4 句变 3 句

---

## 3 句标准话术（任何项目任何阶段）

### 第 1 句：建库 + 跨项目搬判断（项目第一句对话）

> **触发**：新项目第一次对话 / 东哥说"建个新项目/搬素材" / 第一次提到本 skill
> **话术**：「按 wechat-content-mining skill 建本项目的素材库结构。**如有源项目可搬，告诉我源项目路径，我会列出可搬清单让你选 A/B/C**」
> **我做什么**：
> - 检查 `<项目根>/03_写作素材库/` 是否存在
> - 不存在 → 建目录 + 复制 `00_素材索引.md` 模板
> - 存在 → 检查 6 类分类是否齐全 + 提示东哥历史素材状态
> - **东哥提了源项目** → 列出源项目 6 类素材清单 + 让东哥选 A/B/C

#### 跨项目搬的 3 个选项（嵌入第 1 句）

| 选项 | 内容 | 何时用 |
|---|---|---|
| **A（默认推荐）**| 只搬 skill + 索引结构 | 新项目想从 0 干净积累 |
| **B** | 搬 skill + 索引 + 方法论类（📐⚙️🛠）| 新项目主题相近，想复用方法论 |
| **C** | 搬全部 + 主动提示删项目专属 | 东哥明确要求全搬 |

#### 3 类内容搬迁判断标准

| 类型 | 默认选项 | 理由 |
|---|---|---|
| 📐 方法论 | 选项 B 搬 | 跨场景适用（8 条规则在 paiju 用得上，在 GEO 也用得上）|
| ⚙️ 元规则 | 选项 B 搬 | 跨项目适用（4 句话术、memory 架构）|
| 🛠 工具 | 选项 B 搬 | 跨项目适用（CLI 用法、skill 写法）|
| 🧑 个人 IP 底色 | 选项 C 才搬 | 跨项目 = 项目身份错乱（51 岁审计人只属于 024grwangye）|
| 🏗 项目档案 | 选项 C 才搬 | 项目专属（东歌AI 主页 = 024grwangye，不属于 020GEO）|
| 🕳 项目专属踩坑 | 选项 C 才搬 | 跨项目无意义（paiju 写作踩坑 = 020GEO 不做 paiju）|
| 📝 项目专属已稿 | 选项 C 才搬 | 跨项目无意义（建站手记 = 024grwangye 的故事）|

**为什么不默认搬全部**：
- 搬 100 个素材容易
- 删 80 个不相关的难（要逐个判断"要不要留"）
- 新项目 = 新身份，**从 0 干净积累 > 搬 100 删 80**

**3. 主动提示双链状态**

- 选项 A：素材库是空的，没有双链需要修 ✅
- 选项 B / C：双链会断（指向 `../024grwangye/...`），需要本地化修复

### 第 2 句：过程中沉淀（东哥说"这个值得记"时）

> **触发**：东哥说「这个值得记 / 记一下 / 沉淀一下 / 写成素材 / 这个能成文」 或 4 个判断标准中任意 1 条命中
> **话术**：「已记，标 💡 写作素材 + 沉淀到 6 类中的 [X 类]，文件 [filename].md，带 [N] 个公众号标题候选」
> **我做什么**：
> - 不打断当前任务，但**立刻**打开 raw log（`memory/YYYY-MM-DD.md`）
> - 在当前对话进度旁加一段 `💡 写作素材：xxx`
> - 对话结束前**统一**提炼到第二层

### 第 3 句：结束前自动扫（每条对话收尾前）

> **触发**：对话看起来要结束时（东哥说"今天就到这 / 没了 / 收尾 / 结束" 或 长时间没新任务）
> **话术**：「按 7 步流程沉淀今天的内容到 03_写作素材库/」
> **我做什么**（**必跑 7 步**）：
> 1. 扫一遍对话，识别符合 4 个判断标准的内容
> 2. 在 raw log 标 💡 写作素材
> 3. 判断进哪个分类
> 4. 按 5 个模板选一个
> 5. 建文件到 `<项目根>/03_写作素材库/`
> 6. 更新 `00_素材索引.md`
> 7. 交叉引用（[[双链]]）

### 3 句话的使用顺序

```
新项目第 1 次  → 第 1 句（建库 + 跨项目搬判断）  — 一次性
工作中 N 次    → 第 2 句（过程沉淀，按需触发）
对话结束前 1 次 → 第 3 句（自动扫，按时触发）
```

**3 句配合 = 完整闭环**。任何项目、任何阶段，都按这 3 句走，不会漏。

## 3 句话的设计决策（**3 个决策 + 理由**）

### 决策 1：第 1 句用「按 skill 建」而不是「建素材库」

- **候选 A**：「建个素材库目录」
- **候选 B**：「按 wechat-content-mining skill 建本项目的素材库结构」✅
- **理由**：A 太模糊，6 类怎么分、索引怎么建、5 个模板怎么用全没说。B 直接指向 skill，**一句话包含所有规则**。东哥不必每次都重复说「按 X 规则建」。

### 决策 2：第 2 句用「立即记 + 延迟提炼」而不是「立即建文件」

- **候选 A**：「立刻建文件到素材库」
- **候选 B**：「立刻标 💡 写作素材 + 结束前统一提炼」✅
- **理由**：A 打断当前工作流（工作中频繁建文件 = 节奏乱）。B **不打断** + 集中处理（结束前 7 步 = 高效）。**「立即记 + 延迟提炼」是知识管理的最佳实践**（参考 [[auto-save-conversation-facts]] 4 个判断标准）。

### 决策 3：第 3 句「每条对话必跑」而不是「重要的对话才跑」

- **候选 A**：「东哥认为重要时跑」
- **候选 B**：「每条对话结束前自动跑」✅
- **理由**：A 让"重要判断"成为成本 = 东哥累了就不提 = 漏素材。B **机械触发 = 不依赖东哥判断**。**素材积累是肌肉记忆，触发越少越容易忘**（参考 [[auto-save-conversation-facts]] 触发频率规则）。

| 版本 | 变化 | 东哥触发 |

**关键学习**：东哥的 2 次反问（"还有第二句吗" + "第 1 第 4 一样吗"）揭示了 skill 设计最容易漏的 2 个部分：
1. **触发话术**（没话术 = 不知道说什么）
2. **话术之间的重叠**（有重叠 = 4 句变 3 句）
