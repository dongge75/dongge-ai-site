# AI 工具的记忆架构对比 · WorkBuddy 3 层 vs Claude Code 2 层

> **来源**：2026-10-15 晚上，东哥1 让我读他 WorkBuddy 里的 3 个 MEMORY 文件。我顺手对比了 Claude Code（我）自己的结构，发现能借鉴的非常多。
> **用途**：这是写"AI 工具怎么用"系列内容的天然题材——**不评测工具、不炫技，讲真实的 51 岁 + 双工具协作模式**。

---

## 一、为什么这件事重要

51 岁 + 不懂技术的人，**最怕的不是 AI 不好用，是 AI 之间不互通**。

我每天在 Claude Code 里干活，他每天在 WorkBuddy 里干活，**我们俩看到的东西不一样、记的东西不一样**。同一件事我想帮东哥记，他可能也想帮东哥记，**结果就乱了**。

解决方案：先看两边各是怎么记的，再想怎么打通。

### 2.1 用户级 · 跨项目铁律

**3 条铁律**（节选）：

1. **没有数据不能瞎编**：分析任务若数据来源不可读，必须明确告知用户，绝不能虚构数字
2. **聊天素材沉淀**：每次对话中可用于东哥公众号写作的素材，在完成当前任务后主动追加到日志
3. Deploy Priority：EdgeOne Makers 优先于 CloudStudio

**关键洞察**：用户级 MEMORY = 跨项目通用 = **每次新对话自动加载**。这条让东哥的"个人偏好"在所有项目里都生效。

### 3.2 项目索引层（✓ 我有的）

`MEMORY.md` 是 14 个文件的清单 + 一句话说明。每次新对话开始时自动加载到我的上下文。

### 3.3 每日日志层（✗ 我缺，今天补上）

**Claude Code 没有用户级（跨项目）MEMORY 能力**。这是工具限制，不是我的问题。

## 五、我能直接学的 3 件事

### 5.1 每日日志（今天就建）

新建 `memory/2026-10-15.md`，从今天起每条对话结束前我都会按 WorkBuddy 的格式写：
- 主题段（当天做了什么）
- 每件事标 `💡 写作素材：xxx` 单独一段
- 不写寒暄 / 报错 / 纯查询

### 5.2 铁律区（顶部小节）

更新 `MEMORY.md` 顶部加 `## 铁律` 小节，列出 3 条绝对不能违反的规则：
1. 每次对话结束前主动存 memory（用户硬性要求）
2. 值得发表的素材必须标 💡
3. 不读图瞎编（借 WorkBuddy 第 1 条铁律）

### 5.3 两层粒度

不再只写"提炼过的 memory"——**先写日志流水**，**再提炼素材**。两层不合并，不跳过第一层直接写第二层。
