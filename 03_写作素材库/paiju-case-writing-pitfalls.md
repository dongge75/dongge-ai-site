# paiju 写作 5 大踩坑（2026-10-15 当日复盘）

> **一句话**：写「讲别人故事」时，最容易踩的 5 个坑（不是 AI 味，是合理推测 + 工具名 + 步骤清单 + 字数焦虑 + 规则不固化）。
> **来源**：2026-10-15 迭代 7 版才定 8 条规则的过程

---

## 💡 踩坑 1：「杜撰用了后反馈」是隐形高危

**踩坑实录**：
- 第 7 版我加了「他用 AI 后效率明显提升，多个圈友用他的方法后都反馈很好」
- 东哥一眼看出：「**这一句内容提炼的就比较好，每一条中，如果作者内容有用了后的反馈，可以加上，但不能杜撰**」
- 原文只有金句 2「有收获的点点小赞，希望更多的人用起来」

**为什么是隐形高危**：
- 数字看着真实（"多个圈友" = 模糊数字 = 看着像真话）
- 语气像作者（"效率明显提升" = 自媒体常用语 = 不像 AI）
- 难以反查（"用了后反馈" = 没办法在原文搜到对应段落）

**解法**：
- 写每条都问自己：「原文有这句吗？」
- 「圈友用了后效果」一律标 🔍 原文出处，找不到 = 删
- 解 [[paiju-case-summary-8-rules]] 8 条规则第 6 项

**公众号标题候选**：
- 「AI 写内容最危险的不是 AI 味，是『合理推测』」
- 「杜撰反馈的 3 个隐形特征：数字真 + 语气像 + 难反查」

## 💡 踩坑 2：「不写工具名」是个人 IP 站的核心

**踩坑实录**：
- 第 1 版我用「WorkBuddy / CLI / Codex / 飞书 / Obsidian」原文照抄
- 整改后所有工具名 = 0

**为什么重要**：
- 读者看到工具名 = 知道是哪个产品 = 跑去搜 = 跳过你的页面
- 个人 IP 站卖的是「我 + 我的视角 + 我的判断」，不是「工具教程」
- 工具是作者的资产，不是读者的关注点

**解法**：
- 工具名黑名单：WorkBuddy / CLI / Codex / 飞书 / Obsidian / 公众号自动化管线
- 一律改成：「用 AI」「用工具」「搭了一套系统」
- 详见 [[paiju-case-summary-8-rules]] 8 条规则第 7 项

**公众号标题候选**：
- 「个人 IP 站不写工具名 = 不给竞争对手免费广告」
- 「读者记住的是你，不是你的工具：5 个不写工具名的理由」

## 💡 踩坑 3：「字数 < 90 略短 OK，但要在自检表里标出接受」

**踩坑实录**：
- 08 西昂原文是短文（飞书），支持内容有限，最终 78 字
- 东哥要求 100-150 字，但 78 字 < 90 = 略短
- 决策：不要为了凑字数而杜撰，标「接受」+ 给用户看具体短在哪

**为什么重要**：
- 凑字数 = 加废话 = 违反 [[content-style]] 大白话
- 凑字数 = 加杜撰 = 违反 [[no-fabrication-case-data]] 铁律

**解法**：
- 判断标准：80-100 略短可接受
- 在自检表里标「接受」+ 标注「原文是短文/飞书」
- 宁可短但真，不要长但假

**公众号标题候选**：
- 「写作服务交付 = 至少 3 版起步：初稿 + 反馈 + 定稿」
- 「用户描述需求时永远不完整，迭代是必须成本」

## 💡 踩坑 4：「7 版迭代才定规则 = 真实规则挖掘成本」

**踩坑实录**：
- 东哥给 7 次反馈，我才有完整的 8 条规则
- 每次反馈都揭示一个更深的规则：
  - 第 1 版：AI 词堆叠 + 工具名 + 步骤清单（粗错）
  - 第 2-3 版：飞轮机制、找选题、删具体步骤（中错）
  - 第 4-5 版：删 3 条核心感悟、4 大要点（中错）
  - 第 6 版：「159 个」→「159 问生成」（细节错）
  - 第 7 版：杜撰「圈友用了反馈」（严重错）
  - 第 8 版：定 8 条规则

**为什么重要**：
- 第 1 版写完不要觉得「差不多就行」
- 用户每次看都会从新角度发现新问题
- 迭代是必须成本（不是可选项）

**解法**：
- 写作服务交付 = 至少 3 版起步（初稿 + 1 轮反馈 + 1 轮定稿）
- 不要承诺「1 遍到位」= 一定翻车
- 把「我要 N 版」写进交付协议

**公众号标题候选**：
- 「用户描述需求时永远不完整：我的 7 版迭代复盘」
- 「为什么好的内容一定改了 7 遍？」

## 💡 踩坑 5：「规则要写到 memory 才能跨对话生效」

**踩坑实录**：
- 东哥问：「是否写入了底层逻辑，以后都按这个规则去写讲什么吗？」
- 我确认后他才同意改文件
- 写进 [[paiju-case-summary-8-rules]] + MEMORY.md 索引加 1 行

**为什么重要**：
- 写进 1 个 memory 文件 ≠ 跨对话生效
- 必须写进 MEMORY.md 顶部「铁律」区（每次新对话自动加载）
- 同时写一份详细 memory 双链引用

**解法**：
- 关键规则 = 双层存储（铁律区 + 详细 memory）
- 详细 memory 含 6 步自检 + 7 个反例对照 + Why & How
- 关联 [[auto-save-conversation-facts]] 4 个判断标准

**公众号标题候选**：
- 「AI 协作的跨对话知识传递：Memory 的 2 层存储法」
- 「规则不写到 memory = 下次对话全部清零」
